# 專案開發進度與功能報告

**日期**：2026-06-09
**專案名稱**：Auto 2D Drawing System (進階 3D 模型比對與公差 API 整合)

## 一、本次新增與優化之核心功能 (Features)

在本次的開發衝刺中，我們針對「3D 模型進階比對」與「前端使用者體驗」進行了大幅度的強化，主要包含以下亮點：

### 1. 進階 3D 視覺比對模式
原先的比對方式僅有單純的疊加，容易造成視覺遮擋。現在實作了三種專業的比對模式：
- **一般疊加 (Overlay)**：紅色代表舊版、綠色代表新版，以半透明材質重疊。
- **實體+線框 (Solid & Wireframe)**：舊版模型改以「半透明線框」顯示，新版維持實體。此模式能完美凸顯內部幾何的變更（例如：挖孔變深、內部倒角改變）。
- **X光滑桿 (Split Wiper)**：使用 Three.js 的 `clippingPlanes` 實作局部剖切效果，使用者可透過畫面下方的滑桿，左右拖曳即時裁切並對照新舊版本的邊界差異。

### 2. 幾何數據差異報表 (Data Report)
除了視覺之外，我們實作了精準的幾何分析：
- **體積與表面積計算**：利用 `pythonocc-core` 取得模型的實體屬性，並計算新舊版本在體積 (Volume) 與表面積 (Area) 的絕對增減量。
- **外觀尺寸 (Bounding Box)**：抓取 X、Y、Z 三軸的最大邊界框尺寸變化。
此功能讓工程師不僅能「看」到變更，還能有具體的數據支援。

### 3. 模型樹結構對照 (Assembly Tree Diff)
我們深入解析了 STEP 檔案的組合層級 (Assembly Hierarchy)：
- 萃取了 `tree_old` 與 `tree_new`。
- 在前端利用遞迴比對演算法，透過計算物件路徑出現次數，來**自動高亮 (Highlight)** 被「新增」或「刪除」的組件，並以左右並排 (Side-by-Side) 呈現，直覺檢查組裝遺漏。

### 4. 自動化資料清理與批次解壓縮
針對業主提供的雜亂資料結構（多個 `MODULE/M24xxx/3D圖檔/` 內含 `.zip`），編寫了自動化清理腳本，將所有深埋在壓縮檔內的 STEP 檔案安全解壓至正確路徑，簡化後續的資料匯入流程。

### 5. 公差標註脫鉤與外部 API 準備
將原本寫死在 2D 工程圖產生器中的公差數值移除。後端開放了 `/api/tolerances` 的接口，方便未來對接外部機器學習訓練的模型所預測出的公差參數。

## 二、遭遇的困難與解決方案 (Challenges & Solutions)

### 1. 複雜組合件的布林運算導致效能卡死
- **問題**：原先嘗試使用 `BRepAlgoAPI_Cut` 與 `BRepAlgoAPI_Common` 來計算真正的「幾何差異實體」，但遇到大量細節的工業模型時，布林運算耗時甚至超過 10 分鐘，且易引發 OpenCASCADE 核心錯誤。
- **解決**：**放棄實體布林，改用網格分析**。我們將比較邏輯改為直接將新舊模型各自轉出獨立的 STL，並在前端用 shader / clipping / 顏色來呈現差異。這將原本的 10 分鐘縮短到了幾秒鐘。

### 2. React 狀態與 Flexbox 排版衝突導致版面崩潰
- **問題**：實作可拖曳調整寬度的側邊欄時，由於 3D 畫面 (Canvas) 的 `flex: 1` 推擠，加上模型樹因名字過長引發的 `max-content` 撐破版面，導致使用者完全無法拖曳縮小側邊欄。
- **解決**：
  1. 將側邊欄預設寬度改為絕對數值 (320px) 取代自動撐開。
  2. 補上 `flex-shrink: 0` 確保側邊欄不被 Canvas 擠壓。
  3. 為 Tree Node 設定 `minWidth: 0` 以及 `textOverflow: 'ellipsis'`，讓過長的文字能正常顯示省略號。

### 3. Vite + React 熱重載期間的語法解析錯誤
- **問題**：修改載入邏輯時漏了括號，導致 Vite 的 OXC 編譯器拋出 `Expected , or ) but found ;`。
- **解決**：迅速透過日誌定位出 `App.tsx` 中的語法錯誤並修復，驗證了前端工具鏈的嚴謹性。
