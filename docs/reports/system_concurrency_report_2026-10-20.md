# 系統併發與智慧標註壓力測試報告

測試日期：2026-10-20
測試環境：本機 FastAPI/Uvicorn，`CAD_ANALYSIS_MAX_WORKERS=1`、`CAD_ANNOTATION_MAX_CONCURRENCY=1`（預設值）

## 結論

- 目前安全設定下，系統最多同時執行 **1 個模型分析工作**及 **1 個智慧標註生成工作**。這是為了隔離 OpenCASCADE、DXF/PDF/SVG 等非同步安全工作，避免多個重型工作把 API 服務拖垮。
- 三個不同帳號同時要求智慧標註時，1 個成功，2 個在約 0.06 秒內收到受控的 HTTP 429；伺服器持續存活，健康檢查正常。
- 同一帳號用三個工作階段同時要求智慧標註時，1 個成功，2 個在約 0.05–0.06 秒內收到受控的 HTTP 409，證明「每位使用者一次只能有一個標註工作」有效。
- 「同時登入的人數」不等於「同時執行 CAD 重型工作的人數」。目前可以有多位使用者瀏覽與操作，但同一瞬間只放行 1 個標註生成；其他請求會收到可重試回應，而不是無限卡住。
- 這份結果證明保護機制生效，不代表正式硬體的最終容量。要提高同時生成數，應先以獨立 worker/process 隔離 CAD 工作，再逐步調高環境變數並重跑本腳本。

## 已加入的阻塞防護

1. 模型分析採受限 worker pool；同一使用者已有 queued、processing 或 finalizing 工作時，不再接受第二個工作。
2. 分析狀態直到後處理與所有權資料建立完成後才標記 completed，避免前端過早進入結果頁。
3. 上傳與檔案複製改由 FastAPI 工作執行緒處理，避免阻塞主事件迴圈。
4. 前端重新整理後會透過 `/api/jobs/active` 找回目前工作、進度及佇列位置。
5. 智慧標註同時具有每使用者鎖與全域容量鎖；忙碌時快速回傳 409/429。
6. 完全相同的標註輸入會使用已生成的 DXF/PDF/PNG/SVG 快取，不重跑後端標註管線。

## 測試方法與限制

- 使用 `tools/annotation_concurrency_benchmark.py`，讓多個已登入的 Cookie 工作階段在同一 barrier 同時呼叫 `/api/annotation/render`。
- 測試模型為 `BLADE_ASSY-1AC085000H-R01_37f6697b_batch`，零件為 `SHAFT-2AC085010H_1`，每次選取 3 條候選規則。
- 三個臨時管理員測試帳號於測試後皆已停用；密碼未寫入任何報表。
- 本次樣本主要驗證阻塞保護、錯誤回應與服務存活。正式上線容量仍需在部署硬體、真實大型模型及預期工作量下進行長時間測試。
